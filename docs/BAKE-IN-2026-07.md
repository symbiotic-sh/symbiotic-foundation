# Bake-in 2026-07: engine-seam capability flags + standardized queue telemetry

Status: landed 2026-07-02, working tree. This repo's share of the bake-in-now contract
(`bake-in-now-2026-07.md`, kept in symbiotic-mem-bench's `.hermes/notes/` — the ten
irreversibles: cheap now, crippling to retrofit). Implemented here: both halves of
**irreversible #8** — the engine seam carries capability flags, and queue telemetry
(throttle-wait vs http-time, the measured lesson) is a standard shape instead of ad-hoc
trace spelunking. Everything is additive; every persisted artifact still loads.

## What landed

### Engine-seam capability flags (symbiotic-model)

- `ModelCapabilities { context_window: Option<u32>, tool_use, structured_output, reasoning_tier,
  cost_class }` — struct-level `#[serde(default)]`, so a profile persisted before any future field
  existed still loads (`from_str("{}")` round-trip is a test).
- `CostClass` (`free | budget | standard | premium`, default `Standard`) and `ReasoningTier`
  (`none | standard | extended`, default `None`). `ReasoningTier` is deliberately NOT
  `symbiotic_core::ModelTier` — that is selection routing, this is what the model can do.
- `default_model_capabilities(&ModelIdentity) -> Option<ModelCapabilities>` — a catalog fn beside
  `default_model_queue_config`, same convention: known identities get tuned entries
  (deepseek-v4-flash/pro, gemini-3.5-flash / 3.1-pro-preview, gemini-embedding-2,
  qwen3-embedding-8b/4b, nemotron-rerank-free, an ollama/local catch-all), unknown → `None`.
- Attachment point: `ProviderDescriptor::model_capabilities()` — a method resolving
  catalog-or-default, NOT a struct field, so zero constructor/serde breakage anywhere.

Naming caveat: `ModelCapabilities` (this struct, per the contract) is one letter from the
pre-existing `ModelCapability` enum (operation kinds a provider serves: chat/embedding/rerank/...).
Doc comments on both call out the distinction.

### Standardized queue telemetry (symbiotic-queue + symbiotic-trace + run_queued)

- `LatencyStats { count, p50_ms, p95_ms, max_ms }` — nearest-rank percentiles over ms samples.
- `QueueTelemetrySummary { queue_id, queue_wait, throttle_wait, provider }` — the three phases of a
  queued provider call: semaphore/claim wait, rate-bucket/cooldown wait, HTTP.
- `QueueTelemetryAccumulator` — `observe_queue_wait / observe_throttle_wait / observe_provider`
  keyed by plain queue-id string, `summaries()` ordered by queue id. Pure in-memory fold math,
  deliberately decoupled from any recorded trace type: hosts feed it from whatever they already
  persist (existing `model-queue-traces.jsonl` files work unchanged).
- `TimingTrace` gains `queue_wait_ms` / `throttle_wait_ms` (`Option<u64>`, additive): a split of
  `queued_ms`, whose semantics are unchanged. `run_queued` now accumulates cooldown + rate-bucket
  wait across retry iterations and records the split on the success trace
  (`queue_wait_ms = queued_ms − throttle_wait_ms`, saturating). Field names match the
  accumulator's lanes on purpose.

### Tests that pin the guarantees

- `known_model_capabilities_live_in_catalog` — catalog entry values, unknown-identity `None`,
  descriptor fallback to the conservative default, and the `{}` additive-serde round-trip.
- `queue_telemetry_summaries_report_nearest_rank_percentiles` — fixed 1..=100 sample set
  (p50=50 / p95=95), per-queue ordering, empty-lane default instead of a panic.
- `queued_chat_trace_separates_queue_wait_from_provider_time` — extended to assert budget wait is
  attributed to `throttle_wait_ms` and that `queue_wait + throttle_wait` partitions `queued_ms`.

## Compat guarantees

- **All additive.** New types only, plus two `Option` fields on `TimingTrace` — traces recorded
  before the split load with `None`. No existing serialized struct changed shape, no id formats
  touched, no trait changed (the descriptor gained an inherent method, not a trait method).
- **No behavior change on the wire.** `queued_ms`/`provider_ms`/`total_ms` mean what they always
  meant; the rate bucket still charges 1 per request (the rpm-policy fix is untouched).
- **Ship line green:** symbiotic-mem-bench (path-deps on this checkout via `.cargo/config.toml`
  patches) `cargo check` passes; membench's golden vaults are unaffected.

## How to use

```rust
// routing/budget decisions at the seam
let caps = descriptor.model_capabilities();
if caps.tool_use && matches!(caps.cost_class, CostClass::Free | CostClass::Budget) { /* ... */ }

// fold recorded timing traces into per-queue summaries
let mut acc = QueueTelemetryAccumulator::new();
for t in replayed_timing_traces {
    if let Some(ms) = t.timing.queue_wait_ms   { acc.observe_queue_wait(&queue_id, ms); }
    if let Some(ms) = t.timing.throttle_wait_ms { acc.observe_throttle_wait(&queue_id, ms); }
    if let Some(ms) = t.timing.provider_ms      { acc.observe_provider(&queue_id, ms); }
}
for s in acc.summaries() { /* throttle_wait.p50 vs provider.p50 = the diagnosis */ }
```

Diagnosing a slow/serial queue: read `throttle_wait` vs `provider` in the summaries — measure,
don't reason from configured rates. Unknown models resolve to the pessimistic default
(`cost_class: Standard`, never `Free`, even for uncatalogued `:free` ids) so budget routing stays
safe; catalogue a model explicitly when routing needs to rely on more.

## Explicitly NOT done here

- **Consumer wiring in symbiotic-memory** (a `summarize_queue_events` over
  `JsonlQueueEventStore::replay` + re-exports) — deliberately deferred: symbiotic-memory pulls
  foundation from git, so using the new API there breaks its standalone check until foundation
  master is pushed. That step belongs to the memory-repo side after the push.
- **Per-model local capability entries** — the ollama/local catch-all is a deliberately
  pessimistic floor (local qwen-class chat models DO support tool use; we only guarantee cost
  until explicit entries exist).
- **A new engine trait** — the seam already exists as the provider adapters behind the queue;
  capability flags are the new part, not a trait redesign.
- **#1 ids discipline = document-only**; **#2 event envelope / #10 action-classes** are not
  foundation scope — they await the convergence seam-catalog owners.
